# 如何给 Azure 订阅设置用量告警

Azure 里“用量告警”通常指两件不同的事：

| 你想防什么 | 应该配置什么 | 典型例子 |
|---|---|---|
| 费用失控 | **Cost Management 预算告警** | 本月支出达到预算的 80% 时发邮件 |
| 资源配额耗尽 | **Azure Quotas 配额告警** | 某区域的 vCPU 使用率达到配额的 80% 时告警 |

大多数场景说的“订阅用量告警”其实是**费用预算告警**，建议先配置这一项。

> **重要**：预算告警只负责通知，**不会停止虚拟机、禁用订阅或阻止继续消费**。
> 如果需要自动执行关机等动作，要通过操作组调用 Logic App、Azure Function 或 Automation Runbook，并为自动化设置严格的资源范围和审批规则。

## 一、费用预算告警怎么工作

### 什么是 Budget（预算）

Azure Budget 是 Cost Management 中的一条**成本监控规则**。它把指定作用域在一个周期内产生的成本与预算金额比较，并在达到指定百分比时发送告警。

预算由四个核心部分组成：

```text
作用域 + 时间周期 + 预算金额 + 告警条件
```

例如：

```text
生产订阅 + 每月 + ¥20,000 + 实际支出达到 80% 时通知
```

预算可以建在管理组、订阅或资源组等作用域。给单个订阅做总费用告警时，直接使用**订阅作用域**最清晰；如果只想监控某个项目，可以改用资源组作用域，或在预算中按资源组、服务名称、标签等条件筛选。

Budget 不是预充值金额，也不是消费上限。创建 ¥20,000 的预算，不代表 Azure 只允许消费 ¥20,000；即使达到 100%，资源仍会继续运行并产生费用。

### 预算百分比是什么意思

告警中的百分比是**当前成本或预测成本占预算金额的百分比**，不是 CPU、流量、存储或 vCPU 配额的使用率。

计算方式如下：

$$
  ext{预算使用率}=\frac{\text{成本}}{\text{预算金额}}\times 100\%
$$

例如预算金额为 ¥4,568：

| 预算百分比 | 对应金额 |
|---:|---:|
| 50% | ¥2,284.00 |
| 80% | ¥3,654.40 |
| 100% | ¥4,568.00 |

在门户输入“预算百分比”后，“金额”列会自动计算，无需手工填写。

### 实际成本和预测费用的区别

告警条件分两类：

| 类型 | 判断依据 | 适合做什么 |
|---|---|---|
| **实际成本（Actual cost）** | 当前周期内已经产生并进入 Cost Management 的累计成本 | 确认已经花到预算的多少百分比 |
| **预测费用（Forecasted cost）** | Azure 根据当前消费趋势预测本周期结束时的总成本 | 提前发现月底、季末或年末可能超支 |

两种都应该配。实际成本告警回答“现在已经花了多少”，预测费用告警回答“按当前趋势，到周期结束可能会花多少”。

例如月度预算为 ¥20,000：

- 本月已入账 ¥16,000 时，**实际成本 80%** 告警触发。
- 本月只入账 ¥12,000，但 Azure 预测月底会达到 ¥21,000 时，**预测费用 100%** 告警会提前触发。

### 数据不是实时的

Cost Management 的成本和使用数据通常有 **8 到 24 小时延迟**，预算通常每 24 小时评估一次。达到阈值后，通知一般会在评估后约一小时内发出。

所以预算告警适合做成本治理，不适合当成实时熔断器。短时间内突然创建大量昂贵资源时，费用可能在通知到达前就已经发生。

## 二、前置权限

在订阅作用域创建和管理预算，常见角色能力如下：

| Azure RBAC 角色 | 查看预算 | 创建或修改预算 |
|---|---|---|
| Owner（所有者） | ✅ | ✅ |
| Contributor（参与者） | ✅ | ✅ |
| Cost Management Contributor（成本管理参与者） | ✅ | ✅ |
| Reader（读者） | ✅ | ❌ |
| Cost Management Reader（成本管理读者） | ✅ | ❌ |

还要注意：

- 新订阅的 Cost Management 数据可能需要最多 **48 小时**才可用。
- EA 场景下，如果看不到费用，可能是 EA 管理员没有开启相应的费用查看权限。
- 创建操作组及其资源需要对应资源组的写入权限。

## 三、在门户中创建订阅预算

### 1. 进入“成本管理 + 计费”

按截图中的中文门户入口进入：

```text
Azure 门户
└── 成本管理 + 计费
  └── 计费
    └── 订阅
      └── 选择目标订阅
        └── 成本管理
          └── 预算
```

具体步骤：

1. 登录 [Azure 门户](https://portal.azure.com)。
2. 在顶部搜索框输入 **成本管理 + 计费**，打开该服务。
3. 在左侧展开 **计费**，选择 **订阅**。
4. 在订阅列表中按名称或订阅 ID 找到目标订阅，然后点击订阅名称。

### 2. 打开目标订阅的预算页面

进入目标订阅后：

1. 确认页面标题是“**订阅名称 | 预算**”。
2. 在左侧展开 **成本管理**。
3. 选择 **预算**。
4. 页面顶部检查 **范围**，应显示目标订阅名称。
5. 点击工具栏中的 **+ 添加**。

如果页面中已经有预算，可以在列表中看到预算名称、作用域和重置周期。一个订阅允许创建多个预算，但名称必须唯一。

### 3. 填写预算详细信息

在“创建预算”的第一页填写：

| 门户字段 | 怎么填写 |
|---|---|
| **作用域** | 确认是目标订阅|
| **筛选器** | 监控整个订阅时留空；只监控部分成本时按资源组、服务或标签筛选 |
| **名称** | 输入唯一名称，例如 `prod-monthly-budget` 或 `cost-account` |
| **重置周期** | 一般选“每月”；也可按需求选择每季度或每年 |
| **创建日期** | 预算开始评估的日期；门户会把日固定为当月 1 日 |
| **过期日期** | 预算停止评估的日期；到期后预算会自动删除 |
| **金额 (¥)** | 输入每个重置周期的预算金额，例如月度预算 ¥20,000 |

页面会根据历史或预测成本显示“建议预算”。它只是 Azure 提供的参考值，可以按组织批准的额度自行修改。

填写金额后，点击底部 **下一页 >**。如果按钮是灰色，检查所有带红色星号的必填字段，尤其是名称、日期和金额。

### 4. 按预算百分比设置 Alert

第二页的告警表格包含“类型、预算百分比、金额、操作组”：

1. 在 **类型**中选择：
   - **实际成本**：已入账成本达到阈值时告警。
   - **预测费用**：预计周期末成本达到阈值时提前告警。
2. 在 **预算百分比**中输入数值，例如 `50`、`80` 或 `100`，不要输入金额。
3. 确认 **金额**列自动显示正确的换算金额。
4. **操作组**只用于扩展到短信、Webhook、Logic App 或自动化；只发邮件时保持“无”即可。
5. 点击 **管理警报条件**可继续添加告警条件。

建议最少配置：

| 类型 | 预算百分比 | 含义 |
|---|---:|---|
| 实际成本 | 50% | 已经花掉一半预算 |
| 实际成本 | 80% | 已接近预算，需要检查增长来源 |
| 实际成本 | 100% | 已达到预算金额 |
| 预测费用 | 100% | Azure 预计周期结束时会达到或超过预算 |

单个预算最多配置 **5 个告警条件**，阈值范围为预算的 0.01% 到 1000%。

### 5. 填写接收人并创建

在告警条件下方继续填写：

1. 在 **警报接收人（电子邮件）**中输入团队邮箱或值班邮箱。不要只填个人邮箱，避免人员休假或离职时漏掉告警。
2. 最多可填写 **5 个电子邮件地址**。
3. 在 **语言首选项**中选择告警邮件语言；保持“默认”时使用与合同关联的语言。
4. 建议把 `azure-noreply@microsoft.com` 加入邮件系统的允许发件人列表，避免通知进入垃圾邮件。
5. 点击底部 **创建**。

页面提示预算评估将在几个小时后开始。由于成本数据本身存在延迟，创建后不会立即收到告警邮件。

### 6. 创建后复查

返回预算列表并打开刚创建的预算，重点复查：

- Scope 是不是目标订阅。
- Budget amount 的币种和金额是否正确。
- Reset period 是否符合财务周期。
- 实际成本和预测成本条件是否都已配置。
- 收件人是否包含团队公共邮箱。

## 四、推荐的告警阈值

一个实用的默认配置是：

| 条件 | 通知对象 | 建议动作 |
|---|---|---|
| 实际成本达到 50% | 项目负责人 | 检查本月进度是否与消费进度匹配 |
| 实际成本达到 80% | 项目负责人、财务或云平台团队 | 查看成本分析，确认主要增长来源 |
| 实际成本达到 100% | 负责人、管理者、值班渠道 | 决定扩充预算还是缩减资源 |
| 预测成本达到 100% | 项目负责人、FinOps 团队 | 在真正超支前调整资源或预算 |

阈值要结合业务的消费节奏调整。例如月初集中购买预留实例时，50% 告警可能没有意义；开发测试订阅消费波动大，可以把早期阈值设低一些。

如果预算金额是 ¥20,000：

- 实际 50% 会在累计成本达到约 ¥10,000 时触发。
- 实际 80% 会在累计成本达到约 ¥16,000 时触发。
- 预测 100% 会在 Azure 预测月底成本达到约 ¥20,000 时触发。

## 五、用操作组扩展通知和自动化

只发邮件时，在预算里填收件人就够了。如果还需要短信、Azure App 推送、Webhook、Logic App 或 Azure Function，可以关联 **Action group（操作组）**。

在订阅或资源组作用域创建或编辑预算时：

1. 在告警条件页面选择 **Manage action groups（管理操作组）**。
2. 选择现有操作组，或新建一个操作组。
3. 在操作组中配置通知渠道或动作。
4. 保存操作组，再保存预算。

操作组适合做：

- 给 Teams、Slack 或内部告警平台发送 Webhook。
- 调用 Logic App 创建工单。
- 调用 Azure Function 或 Automation Runbook 执行受控的资源处理。
- 向 Azure 移动应用发送推送通知。
